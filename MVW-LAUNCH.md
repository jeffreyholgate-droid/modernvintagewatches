# MVW launch handoff

## Review the preview

Use the [MVW preview](https://mvw-recovery-preview.vercel.app) and [draft recovery PR](https://github.com/jeffreyholgate-droid/modernvintagewatches/pull/1). Application commit `7747e9e` is deployed to the protected preview with its separate Supabase project and Stripe Sandbox.

The deployed release passed 125 automated tests, TypeScript checking, the Vercel build and nine integrated preview checks. The existing £2,770 Breitling sandbox payment remained verifiable. In Admin → Orders, eBay reported £2,164.65 including postage, matching the saved cost, and Stripe reported £0 refunded. The full-refund transition was tested against local PostgreSQL and simulated provider evidence. A new refund and a new hosted Buy Now cancellation were not performed in the sandbox during this pass. The new cancellation/resume behaviour was exercised in the regression suite.

- From the shop, open a product and check its all-in GBP price and source wording. **How ordering works** explains the purchase and inspection sequence.
- In a preview tab, start Buy Now from an available watch. Use Stripe Checkout's return link to check **Resume last checkout**. It must reopen the same session. An expired session requires a fresh customer action. Starting a test session reserves a preview watch until verified expiration or payment.
- In Admin → Orders, choose a paid test order. **Check eBay offer** compares the current item and inbound postage estimate with the saved cost when available. Unknown data stays unknown. Verify the complete seller offer, supplied photos, exact watch and delivery cost on eBay before purchasing. The estimated source cost excludes the cost of sending the watch to the customer.
- **Start sourcing** places an internal hold and checks for existing Stripe refunds. Record purchase only after every watch was bought. Record inspection after confirming authenticity, condition, accessories and the order match in person. Record dispatch only after actual handover on a suitable insured service. Do not change these statuses on the historical sandbox orders unless intentionally rehearsing the workflow.
- If a watch cannot be sourced and nothing has been purchased, record a refund request. It holds the order and records the reason. Create a full refund separately in Stripe Sandbox if running an intentional test, then use **Check refund in Stripe**. Only succeeded, GBP refunds linked to the original payment and totalling the full saved amount close the order. A partial, pending or failed refund remains for review. Refunded watches stay off sale.

## Launch decisions and work remaining

1. **Catalogue rights and sourcing model.** Confirm expressly that eBay's agreement permits this particular retail use of Browse content and that MVW has rights to use seller photos and listing copy. The public display licence describes using content to promote eBay and browse its listings, with restrictions on display, retention and freshness. The current retail checkout is a different use case. If permission is unavailable, use approved supplier feeds or independently sourced inventory with authorised images and descriptions. Confirm source availability and cost for every order and do a commercial margin review before stock is offered. See the [eBay API License Agreement](https://developer.ebay.com/develop/api-license-agreement).
2. **Trading information and policies.** Confirm the legal trading identity, business and returns address, customer support contact, fulfilment regions and realistic delivery times. Prepare the actual terms, cancellation instructions, returns/refund policy and privacy notice using those details. Provide customers with a durable order confirmation and the applicable order terms. See [UK distance selling](https://www.gov.uk/online-and-distance-selling-for-businesses), [online selling](https://www.gov.uk/online-and-distance-selling-for-businesses/online-selling), [returns and refunds](https://www.gov.uk/accepting-returns-and-giving-refunds), and [ICO privacy information guidance](https://ico.org.uk/for-organisations/uk-gdpr-guidance-and-resources/individual-rights/the-right-to-be-informed/when-should-we-provide-privacy-information/).
3. **Fulfilment and exceptions.** Arrange insured carriage covering watches at their actual value and verify packaging, service geography and tracking. The £50 pricing allowance is provisional. Establish an inspection checklist and a customer communication path. The app records whole-order purchase, inspection and dispatch. Partial sourcing, failed inspection, post-purchase cancellations, returns, chargebacks, customer notifications and reconciliation beyond whole pre-purchase refunds still require an operator process and further testing.
4. **Payments and operations.** Rehearse a full sandbox refund with a fresh disposable test payment and verify that the order and its status page agree. Prepare named admin access with MFA, credential rotation, alerting for order/webhook failures and a monitored inventory refresh schedule. The current admin sign-in uses a shared password. Verify live merchant configuration and production rollout, backup and rollback only after approval. Do not treat a successful preview build as launch approval.
5. **Dependencies.** The production dependency audit found no critical or high advisories after this pass. Two moderate advisories remain in the Google SDK's transitive glob/minimatch stack. Those packages are in its file tooling tree. Resolve via an upstream compatible version or a separately tested integration change. An audit is a point-in-time dependency check.

## Database and rollback

The additive order-operations migration is `db/migrations/20261124_order_operations.sql`, after orders and retail pricing. It adds an append-only order history and service-only RPCs. The preview migration was applied after a Windows DPAPI-encrypted backup and a read-back verified existing rows across the six core tables were identical. For alias rollback, the previous ready deployment is `modernvintagewatches-ge9e4mvo0-jeffrey-holgates-projects.vercel.app` (`2937781`). Older preview code can run with the additive tables present. Keep recorded operations for review if reverting application code.
